# 高德地图 POI 景点采集工具：可行方案

> 版本：v0.1（方案评审稿）  
> 日期：2026-10-09  
> 目标：在用户授权且符合高德开放平台协议的前提下，按城市和 POI 类型检索地点，允许地图人工补点，展示结构化结果，并导出 Excel。

## 1. 结论与推荐路线

推荐采用 **“高德地图 JS API 2.0 + 自有后端 + 高德 Web 服务 API”** 的三层方案：

1. 前端用高德 JS API 展示地图、城市边界、标记点、信息窗体和手动选点。
2. 后端持有 Web 服务 API Key，负责城市/区域解析、POI 检索、详情补全、去重、任务队列和导出。
3. Excel 由后端根据已确认的数据生成，保留来源、采集时间、POI ID 和字段完整度。

不推荐将 Chrome 自动化作为主采集方式。高德服务协议明确限制使用爬虫、抓取工具、自动化访问、复制/缓存/下载地图及内部交互数据；若确需脱离高德服务使用数据，应先通过工单取得书面确认。见[高德开放平台服务协议](https://lbs.amap.com/pages/terms/)。

## 2. 需求拆解

### 2.1 用户流程

1. 输入或选择城市。
2. 地图定位到城市并绘制行政区边界。
3. 选择一个或多个 POI 类型：景点、商场、酒店、餐饮、交通设施等；也可输入关键词。
4. 系统在城市边界内分页检索并在地图标点。
5. 用户在地图上点击“补充点”，选择已有 POI 或填写自定义名称/坐标/备注。
6. 右侧表格展示主 POI，支持筛选、编辑、排除、批量确认。
7. 点击“开始采集”，对已确认的主 POI 检索其可用的子 POI/周边 POI。
8. 任务完成后导出 Excel；失败项可重试，无法从 API 获得的字段显示为空并注明原因。

### 2.2 建议的类型预设

| 界面名称 | 高德类别/策略 | 备注 |
|---|---|---|
| 景点 | 风景名胜类 typecode（以官方分类码表为准） | 优先作为 MVP |
| 商场 | 购物服务/商场 | 可进一步按商场、购物中心细分 |
| 酒店 | 住宿服务 | 建议保留酒店等级/品牌为扩展字段 |
| 餐饮 | 餐饮服务 | `tag` 等字段可能包含特色内容，菜品需谨慎标为“可选” |
| 自定义 | 关键词 + 类型 | 允许输入“博物馆”“亲子乐园”等 |

类别配置不要硬编码在前端；后端维护版本化配置，使高德分类码变化时可以更新。

## 3. 高德能力与字段可行性

高德地点搜索服务提供关键字、周边、多边形和 ID 查询四类能力；可用 `city`/`adcode` 限制城市，也可用多边形检索城市边界内的 POI。参考[地点搜索服务 2.0](https://lbs.amap.com/api/webservice/guide/api/newpoisearch/)和[搜索 POI 基础文档](https://lbs.amap.com/api/webservice/guide/api/search/)。

高德 JS API 的 `DistrictSearch` 可以查询行政区中心点和边界，并用 Polygon 绘制到地图。参考[行政区查询](https://lbs.amap.com/api/javascript-api-v2/guide/services/district-search)。

地点搜索 2.0 的详情字段可覆盖：

- 名称、POI ID、类型/typecode、地址、电话、经纬度；
- `business.opentime_today`、`business.opentime_week`（营业时间）；
- `business.tag`（目前主要在美食 POI 下返回的特色内容）；
- `children` 子 POI（需通过 `show_fields` 请求）；
- 文档中的图片介绍/图片相关字段（需以当前 Key 权限和实际返回为准）。

因此“名称、营业时间、经纬度、介绍、部分图片/图片信息”是可行的；**景区图片和完整菜品清单不能在方案阶段承诺必有**。实现时必须记录 `field_status`，区分“有值”“接口未返回”“权限/配额不足”“用户补录”。不得抓取高德网页图片或页面源码来填充缺失字段。

## 4. 总体架构

```text
浏览器前端
  ├─ 高德 JS API 地图（显示、边界、Marker、手动补点）
  ├─ 查询条件/表格/任务进度/导出按钮
  └─ 仅调用自有后端，不暴露 Web 服务 Key
          │ HTTPS
后端 API
  ├─ 城市解析与边界缓存
  ├─ POI 搜索编排（关键词/类型/多边形/分页）
  ├─ POI ID 详情补全与子 POI/周边 POI 采集
  ├─ 去重、限流、重试、审计日志
  ├─ 任务队列与状态机
  └─ Excel 导出
          │ HTTPS + Key/签名
高德 Web 服务 API
```

### 4.1 推荐技术栈

- 前端：React + TypeScript + Vite；地图使用高德 JS API 2.0。
- 后端：Node.js/NestJS 或 Python/FastAPI（二选一）；Axios/httpx 调用 API。
- 数据库：PostgreSQL（含 PostGIS 更佳）；Redis 用于任务队列和限流。
- 文件：对象存储保存用户上传图片或导出文件；不缓存高德受限内容。
- Excel：Node.js `exceljs` 或 Python `openpyxl`。
- 部署：前端静态托管 + 后端容器；生产环境 HTTPS、密钥管理和审计日志。

## 5. 关键功能设计

### 5.1 城市选择与边界

- 输入城市名后先调用行政区查询，解析 `adcode`、城市中心点、边界。
- 以 Polygon 形式高亮边界并自动 `fitView`。
- 检索优先使用 `adcode`；只在无法解析时使用城市文本。
- 若边界过大导致结果量或配额风险，提示用户按区县拆分或缩小范围。

### 5.2 POI 检索

- MVP 使用 Web 服务 API `/v5/place/text`（关键词/类型）和 `/v5/place/polygon`（边界内）。
- 以 `page` + `page_size/offset` 分页，遇到重复 POI ID 时去重。
- 每个类别生成独立查询批次，保留 `query_type`、关键词、城市、时间和原始响应摘要。
- 前端地图只显示已成功解析的坐标；表格按“待确认/已确认/排除/补录”管理。

### 5.3 手动补点

- 地图点击后弹出经纬度和地址反查结果。
- 用户可选择“关联已有 POI”或创建“用户补录点”。
- 用户补录点必须标记 `source=user`，不可伪装成高德官方 POI。
- 支持拖动 Marker 修正坐标、备注、标签和是否纳入采集。

### 5.4 开始采集与子点位

将“开始采集”设计为异步任务：

1. 锁定本次任务的 POI 清单和查询配置。
2. 对有 POI ID 的主点调用 ID 详情；按需请求 `show_fields`。
3. 对景区/商场/酒店等主点按配置获取 `children`；若子 POI 不足，再以主点坐标做周边检索。
4. 餐饮类额外保存 `tag`、电话、营业时间等可用字段；菜品仅在 API 明确返回或用户补录时写入。
5. 做幂等去重：优先 `source + poi_id`，其次使用名称 + 坐标距离阈值 + 地址组合。
6. 记录每条数据的 `collected_at`、`api_version`、`source`、`field_status`。

## 6. 数据模型（建议）

### 6.1 `poi`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID | 系统主键 |
| source | enum | `amap` / `user` |
| source_poi_id | string | 高德 POI ID；用户点为空 |
| name | string | 名称 |
| category | string | 景点/商场/酒店/餐饮等 |
| typecode | string | 高德分类码 |
| longitude/latitude | decimal | 坐标及坐标系标识 |
| address | string | 地址 |
| intro | text | 介绍/备注；区分 API 与用户来源 |
| image_refs | jsonb | 仅保存获授权的图片引用或用户上传引用 |
| opentime_today/week | string | 营业/开放时间 |
| tel | string | 电话 |
| parent_poi_id | string | 子点位所属主点 |
| source_url | string | 仅在授权允许时保存 |
| field_status | jsonb | 字段级完整度/失败原因 |
| collected_at | timestamp | 采集时间 |

### 6.2 `collection_job`

保存城市、adcode、边界版本、类别、关键词、分页参数、状态、错误数、开始/结束时间和操作者。

## 7. API 草案

```text
POST /api/cities/resolve              解析城市与边界
POST /api/search/preview              预览城市内 POI（不落最终采集结果）
POST /api/poi/manual                   新增/修改用户补录点
POST /api/collection-jobs              创建采集任务
GET  /api/collection-jobs/:id          查询进度、错误和统计
GET  /api/collection-jobs/:id/pois     分页查询表格数据
POST /api/collection-jobs/:id/retry   重试失败项
POST /api/exports                      创建导出任务
GET  /api/exports/:id/download         下载 Excel
```

Web 服务 Key 只放在后端密钥管理中。若高德要求签名，签名也在后端生成；前端 JS Key 与 Web 服务 Key 分离，并配置域名白名单、服务端 IP 白名单和最小权限。

## 8. Excel 导出设计

建议至少生成 3 个工作表：

1. **主 POI**：景区/商场/酒店等用户选择的主点。
2. **子点位**：主 POI 内部或周边采集到的餐厅、店铺、设施等，含 `parent_poi_id`。
3. **采集日志**：任务条件、来源、采集时间、失败原因、字段缺失状态。

推荐列：名称、类别、POI ID、父 POI、地址、省/市/区、经度、纬度、坐标系、今日营业时间、周营业时间、电话、介绍、图片引用、菜品/特色、来源、采集时间、数据状态。

导出前做空值检查、超长文本处理、Excel 注入防护（对以 `= + - @` 开头的用户文本转义），并提供 UTF-8 CSV 作为备选格式。

## 9. Chrome 自动化路线的定位

Chrome/Playwright 可以用于：

- 端到端测试地图交互；
- 回归测试城市选择、边界绘制、手动补点和导出；
- 在用户明确授权且产品允许的场景下，辅助完成页面内的人工操作。

不应用于：

- 读取高德网页 Network/内部接口获取未公开数据；
- 批量翻页、模拟点击、截图 OCR 或下载网页图片来替代官方 API；
- 绕过验证码、频控、登录或安全措施；
- 将高德网页内容复制、缓存、下载后作为独立数据库或商业产品分发。

若业务确实必须获得官方 API 未提供的字段（例如完整菜品、长期离线图片库），应先向高德提交商务/技术工单，确认数据授权、字段范围、存储期限、展示方式和导出权，再决定是否实施。

## 10. 配额、稳定性与合规控制

- 先申请 Web 服务 API Key，并核实认证、日配额、QPS、商用和批量导出许可。地点搜索 2.0 文档说明上线使用需通过工单确认流量配额，不能按试用配额直接承诺生产规模。
- 采用令牌桶限流、指数退避、最大重试次数、断点续采和任务取消。
- 同一 POI 详情设置缓存，但缓存期限和字段范围以协议/工单为准；默认不缓存受限地图瓦片、网页内容和高德图片二进制。
- 在 UI 中展示“高德地图/数据来源”及必要的版权和服务声明。
- 只采集业务需要的公开地点信息；对电话等可能涉及个人信息的字段进行权限控制、脱敏和最小化导出。
- 记录 Key 使用量、错误码、响应耗时、命中配额和人工修改历史。

## 11. 分阶段交付

### Phase 0：合规与接口验证（1 周）

申请 Key，确认 JS API 域名白名单、Web 服务权限、配额、`show_fields` 返回字段、图片/商用/存储限制。用 1 个城市和 2 个类型做样例验证。

### Phase 1：MVP（2–3 周）

城市选择、边界绘制、景点/商场/酒店三类预览、地图 Marker、表格、手动补点、详情补全、Excel 导出和错误重试。

### Phase 2：采集任务（2 周）

异步队列、子 POI/周边点位、任务进度、断点续采、字段完整度、审计日志。

### Phase 3：增强（按授权决定）

餐饮特色/菜品、图片管理、多用户权限、历史任务对比、按区县拆分、定时刷新。只有在授权明确时才加入批量离线存储或外部数据源融合。

## 12. 验收标准

- 选择城市后 3 秒内完成地图定位，边界可见且可缩放；
- 每个检索结果均可追溯到查询条件、POI ID、来源和采集时间；
- 同一 POI 不因分页或多类别重复导出；
- 断网、超时、配额错误可显示可理解的状态并支持重试；
- 用户补录点与高德点清晰区分；
- Excel 可被 Excel/WPS 正常打开，主点、子点和日志可关联；
- 缺失图片、营业时间、菜品时不伪造数据，导出中明确标记缺失原因；
- 上线前完成高德协议、商用许可、隐私政策和数据留存期限评审。

## 13. 主要风险与决策

| 风险 | 影响 | 决策 |
|---|---|---|
| API 配额/字段权限不足 | 采集量和字段不稳定 | Phase 0 先做真实 Key 验证，生产配额走工单 |
| 图片/菜品并非稳定 API 字段 | 导出缺项 | 采用字段状态；授权后再接合法第三方数据源 |
| Chrome 抓取违反协议 | 账号、服务和法律风险 | 不作为数据采集主链路，仅做测试/人工辅助 |
| 城市边界过大、结果量过多 | 超时、漏数、费用 | 按区县/网格拆分，提供数量预估和确认 |
| 高德坐标系与其他系统不一致 | GIS 偏移 | 每条记录保存坐标系，禁止静默转换 |

## 14. 最终建议

先做一个“单城市、三类 POI、官方 API、可补点、可导出”的 MVP，并把 `show_fields`、图片、营业时间、子 POI 和配额结果作为接口验收项。待高德书面确认数据使用和存储范围后，再决定是否扩展餐饮菜品、图片持久化以及更大规模的批量任务。

## 15. 桌面原型：省市选择接口

桌面原型已接入旅小略省市目录，侧栏和地图工具栏的城市按钮共用选择弹窗。弹窗支持省市联动、城市名称/拼音搜索、加载状态、错误重试，并忽略切换省份前的过期响应。

- `POST https://api.lvxiaolue.com/api/common/city/provinces`，请求体 `{}`。
- `POST https://api.lvxiaolue.com/api/common/city/cities`，请求体 `{"provinceId":3761}`（江西省示例）。
- 返回结构为 `{"code":200,"data":[{"id":1264,"name":"南昌市",...}],"msg":"success"}`。
- 桌面端通过 Tauri 命令发起 HTTPS 请求；Vite 开发预览通过 `/city-api` 代理请求。

省份和城市 `id` 是旅小略目录标识，不是高德 `adcode`。桌面端现通过高德行政区查询解析城市中心、行政区代码和边界，切换城市后重新定位地图，等待用户点击“开始预览”查询该城市 POI；过期请求不会覆盖新城市的数据。

## 16. 当前桌面业务流程

- 高德 JS 地图显示真实底图、城市边界和 POI 标记；列表与地图可联动，分隔条支持拖动调整宽度。
- 启动和切换城市仅定位地图，不自动查询 POI；用户点击“开始预览”后，通过地点搜索 2.0 查询所选城市、类型和关键词，自动逐页加载每页 25 条，直到接口不再返回下一页或达到 100 页上限，每一页都即时更新列表和地图。显示页数和已加载点位进度，支持取消、失败后从未完成页继续加载；列表搜索、排序和分类筛选作用于已加载数据。
- 采集处理勾选的点位及其子点位，通过详情接口补全字段；对接口返回的子点位逐个查询详情、图片和下一层子点位，按 ID 去重请求、保留父子关联，显示动态进度，支持取消、失败重试和本地任务摘要历史。
- 地图点击补点保存为用户来源，可填写名称、地址、营业时间和备注；接口缺失字段明确显示“未返回”，不生成示例数据。
- Excel 导出当前勾选的已加载点位，包括主 POI、子点位、采集日志与 AI 补充来源四张表，记录 GCJ-02 坐标、来源、时间和字段状态，使用桌面保存对话框选择路径。
- 当前不提供全城穷尽采集、自动周边扩展、断点恢复或历史数据快照；历史保存的是任务摘要。图片使用接口返回的链接在线展示，列表显示首张缩略图，详情显示照片列表；加载失败提供提示和重试。Excel 保存图片链接，未加入图片二进制下载和离线图库。

开发初始配置：将 `src-tauri/config.example.json` 复制为 `src-tauri/config.local.json`，填写 Web 服务 Key、JS Key 和对应安全密钥。该本地文件已加入忽略规则，构建时作为桌面资源加载。运行 `npm run tauri dev`；浏览器预览不执行桌面端高德查询和导出。

## 17. 自定义 POI 类型与颜色

左侧“自定义类型”打开分类管理弹窗，可搜索高德官方分类目录，设置选项名称与代表颜色。新增选项加入左侧类型网格并自动勾选，通过对应分类编码参与真实查询；类型、颜色和勾选状态保存到本地，重启后恢复。支持移除自定义选项和修改已有类型颜色。

地图标记、左侧选择框和列表分类标签共用颜色配置，默认景点为绿色、商场为蓝色、酒店为橙色、餐饮为红色。更具体的自定义分类优先于宽泛默认分类，例如咖啡厅可使用独立颜色；移除后恢复默认分类。官方分类目录来源及版本见 `src/data/README.md`。

## 18. 子点位采集与展示

高德 `v5/place/detail` 的 `children` 为嵌入式列表，公开请求参数没有子点位分页游标，不能通过 POI 搜索的页码来翻它的下一页。应用保留接口返回的全部子点位，并批量查询每个子点 ID 的完整详情；详情返回下一层时继续发现和查询，直到队列为空或用户取消。同一 ID 只查询一次，多个父点的关联分别保存；循环关联不会导致无限查询或展开。此流程收集的是接口可返回的关联，不承诺覆盖高德未开放的全部内部子数据。

主列表显示每个点位的直接子点数量，采集结束后自动展开当前页的子点列表，可查看子点缩略图、图片数量、营业时间、坐标、采集状态和详情。多层子点可继续展开；单击详情显示父点名称和接口返回的全部照片。详情查询失败保留原始子点摘要并显示错误，支持独立重试；取消后下次采集继续处理待完成的子点。

导出“子点位”表包含所选主点的多层后代，保留直接父 POI ID；任务日志记录子点详情的总数、完成及失败数量。

接口参考：https://lbs.amap.com/api/webservice/guide/api/newpoisearch

## 19. 景区内部点位与关联子点的区别

`children` 只表示高德详情接口维护的关联子点，不表示景区地理范围内的所有 POI。地图底图上展示的点位，也不能全部通过该字段获得。实测橘子洲详情返回 7 条关联子点，但范围搜索能够发现更多独立点位。

点位详情新增“地图圈选范围，查找内部点位”。在地图沿边界逐点连线（绘制期间只显示未闭合折线），至少添加 3 个顶点，双击结束后自动闭合成多边形，使用 `v5/place/polygon` 显式搜索所有大类（不受左侧类型选择限制），每页 25 条逐页加载；客户端再次检查坐标是否位于圈选范围内，按父点位与 POI ID 去重。补充点位自动查询详情、图片和接口关联子点，在展开列表中区分“范围内点位”与“高德关联子点”。展开后的点位也显示在地图上，Excel 增加“关联方式”列。

同一搜索条件最多返回 200 条数据，达到上限会显示提示，可进一步圈选更小范围补充。取消或切换城市会停止后续查询并忽略过期响应。中断后保留已经发现的点位，详情待采集或失败项可通过采集/重试补充。此功能不承诺穷尽高德地图全部标注。

高德 AOI 边界接口 `v5/aoi/polyline` 属于需开通权限的高阶服务；2026-10-09 当前配置 Key 实测返回 `INSUFFICIENT_PRIVILEGES / 10012`，因此当前使用用户圈选范围，不凭 POI 中心点或名称猜测景区边界。

参考：[搜索 POI 2.0](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch)、[AOI 边界查询](https://lbs.amap.com/api/webservice/guide/api-advanced/search)。


## 20. 软件内配置高德密钥

“设置”提供 Web JS Key、对应的 JS API 安全密钥（securityJsCode）以及 Web API Key 三个输入框，默认隐藏，可切换显示。保存前会去除首尾空格并校验密钥格式；保存失败不会替换运行中的配置。定位、查询或采集期间暂不允许保存，以避免同一任务切换密钥。

保存到 Tauri 用户配置目录的 `map-keys.json`，采用临时文件写入后替换，macOS 文件权限为 0600。启动优先读取用户设置，未配置时回退开发/打包初始配置；缺少配置也可以启动并进入设置。Web API Key 保存后立即用于后续请求；JS Key 或安全密钥修改后需重启软件，使地图 SDK 使用新配置。密钥不存入 localStorage，也不包含在 POI 导出和历史任务中。

## 21. AI 客户端控制：MCP、CLI 与 Skill

设置新增“AI 控制 / MCP”，工作台请求监听器就绪后自动开启，退出软件时关闭；不再需要人工开关。服务仅监听 `127.0.0.1` 的动态端口，使用独立 Bearer 令牌，校验 Host 与 Origin，不开放跨域访问。连接文件位于用户配置目录 `automation-connection.json`，macOS 权限为 0600，关闭服务删除文件。高德密钥不出现在 MCP 工具、状态、导出或连接文件中。

同一套工作台业务通过三种入口调用：

- **MCP stdio**：运行客户端内置可执行程序的 `--mcp-stdio` 模式，无需安装 Node.js、Python 或其他运行环境。设置中复制 stdio 配置，填入客户端 MCP 配置；桥接器只向 stdout 输出逐行 JSON-RPC，自动读取本次服务的地址与令牌，重新开启服务无需重新复制令牌。
- **MCP Streamable HTTP**：连接设置中显示的 `/mcp` 地址，请求头带 `Authorization: Bearer <本地控制令牌>`。服务采用无会话 JSON 响应，不提供 SSE（GET 返回 405），支持协议版本 2025-11-25、2025-06-18、2025-03-26、2024-11-05。端口与令牌每次开启改变，HTTP 客户端需要更新配置；各客户端 URL、请求头字段名称以其文档为准。
- **CLI / Skill**：默认跨客户端通道。客户端可执行程序提供 `status`、`tools`、`call`、`describe`、`doctor`、`open` 和 `skill install`，并兼容旧 `--cli` 模式；与 `automation/map-data-studio/SKILL.md` 一起打包。Skill 安装命令备份并复制文件，当前 AI 会话仍需由对应客户端重新加载。
- CLI 小参数使用 `--args`；批量补全、多边形坐标与复杂模板规则使用 `--args-file` 或 `--stdin`，单次 JSON 对象上限 16 MiB。文件型数据只传路径，结果列表继续分页，避免系统命令行长度和 AI 上下文限制。

本机控制接口为 `POST /api/control`，请求体 `{"action":"get_status","arguments":{}}`，使用相同认证。MCP 公开工具目录由 `automation/tools.json` 维护。支持读取省市、切换城市、查询条件、逐页查询、分页读取主点与子点、读取全部图片链接、勾选纳入、递归详情采集、用户多边形范围补点、取消、手动补点、自定义类型、备注、历史与 Excel 导出。

长任务立即返回 `operationId`。CLI 可用 `call ... --wait` 或 `wait <operationId>` 在本机等待，MCP 使用 `get_operation` 读取单个任务的状态、阶段和耗时；仅诊断时读取完整 `get_status`。当前会话保留最近 50 次 AI 操作。并发客户端不能启动相互覆盖的修改；仍可读取状态和已经加载的数据。取消保留已完成结果。城市定位、Excel 写入不能取消。关闭控制服务停止新请求，已启动的业务任务由工作台取消按钮处理。

AI 控制与 GUI 共用数据：切换城市清空现有点位，只定位不查询；`start_query` 逐页加载接口可返回的结果并显示到地图；AI 调用 `start_collection` 默认只查询指定主点详情，明确传 `includeChildren:true` 时才递归采集关联子点。桌面界面与范围采集仍按完整采集流程处理。`list_pois` 每页最多 100 条，指定 `parentId` 返回直接子点，`get_poi` 返回 API 提供的全部图片 URL。`search_area` 使用明确提供的 GCJ-02 多边形，不猜测官方景区边界。

CLI 示例（内置程序及连接文件绝对路径以设置中显示为准；Windows PowerShell 的引号路径前加 `&`）：

```sh
'/path/to/map-data-studio' status --json
'/path/to/map-data-studio' tools --json
'/path/to/map-data-studio' call list_provinces
'/path/to/map-data-studio' call list_cities --args '{"provinceId":3761}'
'/path/to/map-data-studio' call select_city --args '{"provinceId":3761,"cityId":1264}'
# 读取 status，等 select_city 的 operationId 完成后再执行后续步骤
'/path/to/map-data-studio' call set_query --args '{"categories":["景点"],"keyword":"博物馆"}'
'/path/to/map-data-studio' call start_query
# 等查询完成后分页读取或采集；采集完成后导出
'/path/to/map-data-studio' call list_pois --args '{"page":1,"pageSize":100}'
'/path/to/map-data-studio' call start_collection --args '{"includeChildren":false}' --wait --json
'/path/to/map-data-studio' call export_excel --args '{"path":"/absolute/existing-directory/南昌-POI.xlsx"}'
```

Excel 自动导出需要绝对 `.xlsx` 路径和已存在目录，拒绝覆盖文件；等待操作完成并得到返回路径再报告保存成功。导出仍包含主点、后代点位与任务日志。当前未提供远程公网服务，云端 AI 客户端无法直接访问用户电脑的 localhost；此入口面向可运行本地 MCP 或访问本机 HTTP 的 AI 客户端。

协议参考：[MCP transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)、[MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。

控制程序使用 Rust 实现，复用桌面应用的可执行文件。`--mcp-stdio`、顶层 CLI 命令及兼容的 `--cli` 在初始化桌面窗口之前分流，不读取高德密钥。业务命令会在需要时启动工作台。设置生成的 MCP 配置直接指定该程序及模式参数；打包后用户无需准备编程环境。Node.js 仅用于项目开发、前端构建和开发测试。

## 22. 用户 Excel 模板与 AI 补充字段

支持“提供空白 Excel → AI 读取模板 → MCP 采集指定城市景区 → AI 查询缺失字段 → 按原模板生成填写版 Excel”的流程。

- `inspect_excel_template`：同步读取本机绝对路径的 `.xlsx` 文件并直接返回结果，无需轮询；结果包含工作表名称、指定表头行的列名和编号、样例行、合并区域、数值格式以及内置字段目录。AI 据此确定目标工作表、表头、首个数据行及列映射。云端附件必须先由 AI 客户端的文件工具放到运行桌面客户端的电脑；MCP 不能直接读取另一台电脑或云沙箱中的附件。
- `get_template_gaps`：根据映射字段，分页检查当前纳入点位的缺失项，返回点位 ID、名称、城市、地址和缺失字段。高德之外的字段使用 `custom:门票价格`、`custom:景区等级` 等键。可纳入所选主点的子点；读取全部初始缺失页后再回填，避免更新过程中分页位移。
- `supplement_poi`：每批最多 10 项，接收 AI 查到的值、来源 URL 和可选来源标题，记录回填时间。AI 只能补充缺失字段或模板自定义字段，不能覆盖高德已有值；原始字段不修改。补充值作为独立记录保存在当前点位中，详情弹窗可查看内容和来源；重新采集详情保留补充记录。与当前点位数据一样，重新查询或切换城市后不保留，需先导出。
- `export_excel_template`：按 `columnMap: [{column: 1, field: "name"}, {column: 2, field: "custom:门票价格", valueType: "number"}]` 写入指定工作表的空白区域。保留原有表头、样式、列宽、其他工作表和已有公式；复制首个数据行映射列的样式及行高。数值列可显式使用 `valueType: "number"`，不合法数字会报错。禁止写入已有内容、公式或合并单元格；禁止覆盖已有文件，输出一份填写版副本。

模板导出增加独立“AI补充来源”表，逐个记录目标单元格、点位、字段、补充值、来源和时间，以及仍缺失的字段。返回写入行数、缺失总数、前 200 项缺失清单与输出路径。`requireComplete: true` 在仍有映射字段缺失时阻止导出；默认保留空白并记录缺失原因。普通 Excel 导出也使用原始值优先、缺失时采用 AI 补充值的规则，并增加完整 AI 补充来源记录。

外部检索由连接的 AI 客户端承担，需要该客户端具有联网搜索/浏览工具。MCP 不内置另一个大模型或通用搜索服务，也不能保证所有模板字段都能查到。Skill 指导 AI 优先查景区官网等可靠当前来源，核对名称、城市和地址，附真实引用；无法确认的信息保留为空，不依靠模型记忆编造。软件校验来源链接格式，记录“AI 提供，附引用来源”，不声称自动核实网页内容。

当前支持普通 `.xlsx` 表格模板，不支持旧版 `.xls`、加密或宏模板；不计算或向新行自动扩展公式。图表、透视表等复杂 Excel 功能的保真不作保证，需要简化模板或由 AI 客户端的专业电子表格工具处理。


## 23. AI 发起用户圈选与子点位模板导出

- 新增 `request_area_selection`：AI 可按唯一主点位名称或明确 ID 启动现有地图圈选模式。重名必须先核对地址与 ID，不猜测景区边界。
- `get_status.areaSelection` 返回 requestId、父点位、状态、圈选坐标、完成时间、子点数量与错误/提示；状态依次为 awaiting_user、collecting、completed，另有 failed/cancelled。用户双击闭合后自动运行范围搜索及详情图片采集。等待圈选时拒绝其他 MCP 数据修改；读取状态与点位不受影响。
- `get_template_gaps` 与 `export_excel_template` 增加 parentId、childrenOnly、poiIds 参数。指定 parentId 时作用于该点及后代；childrenOnly:true 排除父点且必须有 parentId；poiIds 可进一步筛选该范围内的子数据，不修改全局纳入勾选。范围外或重复 ID 被拒绝。
- AI 在同一圈选请求 completed 后，读取子点、映射模板、检索缺失事实并有来源回填，再仅导出选定子点的新 Excel。失败、取消、零子点不能冒充完成。软件不会主动唤醒已结束的 AI 会话，恢复对话后需再次读取状态。


## 24. 合并查询与采集入口

左侧按钮改为“开始查询并采集”，逐页查询结束后自动调用现有详情/子点位/图片采集；列表上重复的“开始采集”按钮移除。查询失败或取消时不自动进入详情采集，保留已加载记录；详情阶段可用“取消采集”停止，失败记录仍可重试。范围圈选流程保持自动采集。

AI/MCP `start_query` 默认只分页查询列表；只有明确传 `autoCollect:true` 才在同一个 operationId 内继续采集全部详情和关联子点。推荐先筛选，再用 `start_collection({selectionId,includeChildren:false})` 只补采入选主点；只有用户需要关联子点时才传 `includeChildren:true`。桌面界面的人工查询仍维持查询后完整采集。保留 start_collection 接口用于定向采集和失败重试。


## 25. 手动补录父点的范围采集

手动补录点位只要具有有效 GCJ-02 坐标，即可从详情启动地图圈选，MCP request_area_selection 同样支持。用户可在重开软件后补录名称和位置，无需先做全城查询，再圈选范围查询内部点位。手动父点不请求高德详情；范围搜索结果按本地父点 ID 关联，采集高德子点详情及图片，继续支持递归子点、失败重试与父点范围模板导出。此功能不是历史数据/边界持久化，重开后需要重新补录及圈选。


## 26. 高德原始字段全链路保留

所有 POI（主查询、圈选、关联子点及详情）保留 raw 原始对象和 rawRecords 各次 POI 响应快照。后续详情缺项不清除首次查询已有值，图片链接合并去重，未知 business/顶层字段保留。普通 Excel 提供评分、标识、别名、人均等常用列，动态展开原始字段列及“高德原始响应”快照表；超长内容分段写入“长字段完整值”，可按顺序拼接恢复。

MCP get_poi 暴露 raw/rawRecords/rawFields，模板映射和缺项工具支持 rating、keytag、rectag、alias、cost、businessArea、parkingType 及 raw:business.rating 等原始路径。已有原始值不能由 AI 覆盖；缺项补充和来源记录继续独立保存。keytag 保留高德原标识，不推断未明确提供的景区认证级别。历史会话/旧版本已丢弃字段需要重新查询，当前会话原始数据需导出后保存。


## 27. 景区内部点位优先 AOI 边界

界面“查询景区内部点位（优先 AOI）”和 MCP `request_area_selection` 默认先按高德 POI ID 请求 `v5/aoi/polyline`。成功后使用完整边界过滤分页检索结果并采集详情、关联子点和图片；长边界用外接矩形检索避免超长 URL，不简化原始顶点。原始 AOI 响应存入父点 `raw.aoiBoundary`，参与原始数据导出。

只有无可用边界、接口异常（含权限限制）或手动补点没有高德 ID 时，才进入 `awaiting_user` 并提供 `fallbackReason`。用户明确选择手动时可传 `manual:true`。状态增加 `resolving_boundary`，完成后才继续模板补全及导出。范围查询仍受单次条件 200 条限制，不能保证所有地图标注；达到上限会保留提示。


## 28. 独立联网补图与高德图片自动落盘

POI 列表工具栏增加“联网补图”，详情可对单点补图，弹窗默认每点3张、原图、必应、最小宽600像素，可选百度、比例、子点范围及目录。3:4／4:3／1:1／16:9按中心裁剪得到精确比例，不放大；搜索只提供候选归属。使用 Rust 原生搜索解析、下载和图片处理，不需要用户安装 Python 或 Node。

数据详情采集结束后自动保存纳入范围的高德图片，原图不裁剪，不触发搜索引擎。默认保存到系统图片目录下 Map Data Studio，设置或补图弹窗可更改；按点位名称建目录，同名 ID 冲突追加短标识。文件按内容摘要命名去重，images.json记录 ID、名称、搜索词及来源、路径和尺寸。Excel 提供 downloadedPhotos、imageSources 字段。

MCP新增 download_images，只在用户明确提出补图时调用，支持点位范围、数量和比例。get_status.imageResults提供请求/实际张数及失败原因，不能因长任务完成就宣称达到指定张数。搜索网站页面变化、验证码、失效链接会导致不足，任务保留成功文件。取消阻止后续点位下载，当前后端请求可能仍完成并落盘。


## 29. 内置 Playwright 百度图片浏览器

百度图片由 Rust 启动随包 Node.js 和 Playwright Chromium，打开可见搜索页，从响应和页面提取原图地址，解码 objURL，并优先使用 replaceUrl 中的原图和来源链接。遇到验证码时显示等待用户验证状态，约五分钟等待后超时报错；用户完成后继续，关闭浏览器／取消操作会终止。自动下载高德图片不启动此浏览器。

为避免 Chromium 本地网络权限弹窗阻塞，导航前使用 grantPermissions([]) 拒绝百度权限请求。浏览器沿用显式 HTTP(S)/SOCKS5 代理环境配置；Cookie 保存在专用图片浏览器目录，不读取用户日常浏览器配置。

构建时 npm run prepare:image-runtime 下载并按官方 SHA256 校验 Node.js 24.21.0，下载对应 Playwright Chromium，放入 src-tauri/image-runtime；该生成目录和缓存不进源码。Tauri 构建自动准备资源，已准备时可以离线复用。安装包包含运行时，用户无需安装 Python/Node/Chrome。打包资源随操作系统和 CPU 架构准备，本次为 macOS arm64；其他系统需在对应环境构建测试，Linux 的浏览器系统库仍须发行版验证。


## 30. 统一存储设置与图片原图／尺寸

设置里新增 Excel、图片、其他资源三个保存目录，默认系统文档/Map Data Studio 下的 Excel、Images、Resources；保存后立即生效，支持恢复默认，历史图片目录配置迁移保留。普通 Excel 导出对话框默认打开配置目录，MCP get_storage_settings 提供默认和实际位置，明确输出路径仍优先采用。资源目录是附件保存位置的预留设置，不移动已下载文件或程序资源。

百度移除缩略图回退，只提取原图地址。补图弹窗与 MCP 支持任意整数宽高比例、输出 width/height、最小 minWidth/minHeight；尺寸必须匹配比例且不放大。原图默认保留原字节，裁剪／缩放结果另存，记录 originalPath、originalWidth、originalHeight，可通过 originalPhotos 映射导出。


## 31. 修正图片尺寸与比例为百度搜索条件

尺寸和比例改为原生百度搜索参数，停止下载后的裁剪和缩放。实测页面：imgratio 1细长竖图、2竖图、3方图、4横图、5细长横图；z提供尺寸分类，自定义width/height传入搜索URL。ratio=3:4映射竖图分类，不代表百度支持精确3:4参数。界面改为搜索比例、搜索尺寸分类、自定义搜索宽高。原图落盘字节不变，返回实际宽高；不符合指定自定义尺寸会跳过并报告不足。此前章节中处理图片的行为被本节取代。


## 32. 长沙景区图片完整流程实测修正

真实客户端查询“长沙市／景点／景区”返回199主点与235关联子点，有图点位367。首轮自动保存高德图片发现GIF原图被格式白名单拒绝及个别连接读取中断。新增GIF支持，保留所有帧的原始字节；图片临时请求／响应读取错误最多尝试3次，404等永久错误不盲目重试，取消时停止重试。测试记录与Excel副本存放本机临时目录，复测结果以本次测试报告为准，不将单一搜索条件视作长沙所有景区覆盖。


## 33. 图片按需保存，百度批次浏览器复用

查询／采集阶段仅取得图片链接。Excel 导出默认不下载图片；明确传入 `photoPoiIds` 时只保存指定导出行的高德原图，模板映射 `originalPhotos`、`downloadedPhotos` 或 `imageSources` 时保存实际导出行。高德图片下载不会触发搜索引擎。

联网补图只由按钮或明确AI指令启动。百度每个批次共用一个浏览器及Cookie，每次景区搜索默认间隔8秒，可设3至60秒；页面资源未加载或验证超时时停止后续搜索。桌面客户端可在存储设置中配置图片浏览器代理，解决未继承开发环境代理导致CSS/JS加载失败的问题。默认不强制代理，用户填写当前网络服务器后生效。


## 34. AI 模板导出的单元格与营业时间格式

`export_excel_template.columnMap` 每列除字段映射外，还支持 `numberFormat`（Excel 显示格式）、`wrapText`（自动换行）。未指定时继承模板样式，`valueType` 继续支持文本与数值。营业时间是区间文本，用 `textFormat: "openingHours"` 规范化明确时间；`timeFormat` 支持 `HH:mm`、`H:mm`、`H点mm分`，`rangeSeparator` 默认 `-`，可设 `至` 或 `—`。规范化保留星期、季节和最晚入园等说明，不改原始 POI，不将未知说明转换为猜测的时间。

例如 AI 可将营业时间列映射为：

```json
{"column":3,"field":"weekHours","valueType":"text","numberFormat":"@","textFormat":"openingHours","timeFormat":"HH:mm","rangeSeparator":"-","wrapText":true}
```

`周一至周日 9：00 — 17:30` 写为 `周一至周日 09:00-17:30`。`全天开放` 和 `暂停营业` 保留原文。格式参数在填写前验证，失败时不产生部分单元格写入。


## 35. 默认景区导出采用杭州标准表

依据用户提供的杭州.xlsx，内置34个具名列的表头、列宽和样式元数据，不依赖外部路径，也不包含杭州样例记录。景区和手动景区导出第一张表为“景区数据”，字段包括省市区、简介、人气、坐标、评分和等级、预约、开放及停止入园、票价、推荐和交通等。默认主景区不含子点；明确包含或单独导出子点时使用相应范围。完整原始数据、AI来源与日志仍保留附表。其他类别保留通用导出，指定模板优先。

`get_default_export_format` 提供列顺序、字段映射、样式和格式约定。AI要求补齐默认表时，读取 fields 后检查缺项、附来源补全，再调用 export_excel。未知热门指数、预约、票价等均留空。景区等级仅提取明确A等级；停止入园仅提取明确的单一时刻，各季节不一致则留空。全天开放按例表表示为00:00-00:00；复杂星期和季节说明保留，附表保留原始完整数据。示例第35列没有表头，不作为标准字段。


## 36. AI筛选与补全任务的MCP流程

AI将自然语言条件和数量转成filter_pois或create_poi_selection参数；支持前10、前50以及有序推荐名单。返回selectionId可复用于缺项检查、补图和导出，数据集变化后失效。实测客流须有来源且同口径；评分排序、AI推荐都不能冒充客流，数值缺失返回shortfall。

create_supplement_task接收补全instruction、fields及范围，supplement_pois批量回填已核实值与来源，整批先验证。get_supplement_task实时返回剩余缺项。模板导出附筛选与补全指令审计表，并支持photoPoiIds限制图片范围，空数组不下载。任务描述不表示已完成，也不会使MCP自动调用搜索或模型。

## 37. 默认AI导出补全与关联时间

AI执行景区Excel导出时，默认研究全部映射缺项，不再要求用户额外声明补票价。`get_default_export_format.enrichmentPolicy`提供时间、票价与费用、预约、攻略、简介与等级、热门指数六组规则；`create_supplement_task`省略fields时采用34个杭州标准字段，并在任务及状态返回各组完整缺项统计，不受第一页100项截断影响。用户自定义模板仍传全部实际映射字段，明确仅原始导出可跳过联网研究。

标准表闭馆列映射为closingTime：优先有来源的custom:闭馆时间，否则提取明确闭馆规定；单个营业区间结束只标记“营业结束，按高德开放时间整理”，不能冒充已核实闭馆规定。openingHours单独整理开放区间，lastEntry只提取明确截止入园规则；季节、星期及多场次保持条件，不能从结束时间减半小时。全天开放00:00-00:00且不假设停止入园。原始hours/weekHours及原始接口响应不改写。模板审计记录推导依据或原有补充来源。

AI逐项检索成人、学生、儿童、老人票及费用明细，明确免费才填0，不根据成人票猜测折扣；价格条件保持文本。攻略建议需要区别于官方事实，时间、班次、距离、优惠资格等需核实。MCP不内置AI模型：上述研究由连接的AI按照技能执行，本机直接导出仍只能使用已有数据；无法证实的缺项留空并说明。

## 38. 用户逐列AI补填规则与价格格式

create_supplement_task.fieldRules支持field、column、instruction、valueType、maxLength和format。用户提供的属性覆盖同字段默认属性，未提供的保留。MCP返回实际合并规则，在任务内批量回填时校验类型、字数及ticketPrice格式，整批失败不部分写入；自然语言内容要求由AI执行。columnMap.instruction及任务规则进入模板导出的指令审计表。format:original可明确解除默认票价格式校验；同源字段在多列要求不同内容时需使用不同custom字段。

以用户票价截图为准：成人/学生票为数字，儿童/老人允许价格 (简短年龄/身高条件)。不在票价列写季节、国籍、证件或套餐说明，完整信息写费用明细；选择导出日期适用的基本门票价格，不能自动截取首个数字。标准景区表对不符合票价格式的值报错，不静默把长文字当价格导出。原始来源与补充历史仍保留。
