# 开发与 GitHub Actions 发布

## 本地开发

需要 Node.js 24、Rust stable、对应系统 Tauri 2 构建工具。Windows 需Visual Studio C++/Windows SDK及WebView2，Mac需Xcode命令行工具。

```sh
npm ci
npm run tauri -- dev
npm run build
cargo build --manifest-path src-tauri/Cargo.toml
npm test
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

本地可将src-tauri/config.example.json复制为config.local.json填写自己的密钥，该文件忽略提交，仅debug开发作为兜底。发布版只使用用户本机配置或空示例，资源清单不能包含config.local.json。

## 发布新版本

同步package.json、package-lock.json、src-tauri/Cargo.toml、Cargo.lock及tauri.conf.json的应用版本，提交代码后：

```sh
git push origin main
git tag v0.1.0
git push origin v0.1.0
```

自动流程位于.github/workflows/release.yml，也可在Actions手动输入版本标签。版本校验拒绝标签与应用版本不一致。GitHub内置GITHUB_TOKEN负责创建Release、上传附件，不需要将个人密码或高德密钥配置到Actions。

三个原生runner分别构建Windows x64、Mac ARM64和Mac Intel，避免浏览器资源与目标架构不一致。流程先构建前端和准备内置Node/Chromium，再编译原生测试程序，运行JavaScript与Rust测试，构建Tauri安装包。矩阵全部通过后才公开草稿Release；失败检查对应job，不发布缺平台的半成品。

发布资源：系统安装包、稳定命名完整应用ZIP及SHA256、中文技能ZIP、两种安装脚本和MCP清单。压缩包较大，单个附件需要在GitHubRelease允许的大小内。安装脚本依赖同Release命名和SHA256，改命名需同步脚本。

## 签名与授权

当前构建未配置Apple开发者签名/公证或Windows代码签名，不应声称签名完成。若后续需要无警告发行，由维护者申请证书并按Tauri官方签名文档添加受保护的Actions Secrets；不要提交证书或密码。普通用户按系统提示完成首次启动，不通过脚本降低系统保护。

豆包连接器无已核实公开自动注册API，安装程序生成配置及技能；AI可通过客户端界面继续设置。不要修改未经文档支持的私有数据库，也不要承诺云端AI可以直接连接用户127.0.0.1。
